# V2.2.9 施工档案详情（App）

## 1. 需求概述

为 App 提供施工档案的只读详情页，供用户查看施工项目的基本信息、建设/监理/施工方信息、关联资源和档案资料完整情况。

本需求由 Web 端《V2.2.9 施工档案详情》转换而来。移动端采用原生导航页、信息卡片和纵向列表，不使用 Web 端的 `ProDescription`、`SuperTable`。

## 2. 页面信息

| 项目 | 说明 |
| --- | --- |
| 页面名称 | 施工档案详情 |
| 页面类型 | 只读详情页 |
| 页面入参 | `id`：施工档案记录 ID，必填 |
| 详情接口 | `GET /xfy/api/data/v2/roomBuildRecord/record/detail/:id` |
| 推荐入口 | 资源详情 → 安全管理 → 资源施工档案列表，点击项目名称进入详情 |
| 路由 / 实现路径 | 当前项目未存在对应页面与路由，需在开发阶段确认后新增 |

### 2.1 页面结构

页面使用 `SafeScreenView + Head + ScrollView` 的标准 App 布局：

1. 顶部导航栏：返回按钮及“施工档案详情”标题。
2. 任务信息卡片：展示施工项目核心字段。
3. 参建单位卡片：展示建设方、监理方、施工方及其负责人。
4. 内容分段：使用 `TabWrap` 或分段锚点呈现“关联资源”“附件资料”；具体组件以新增页面所在模块的现有模式为准。
5. 本期不提供编辑、删除、补充资料等写操作。

## 3. 页面内容

### 3.1 任务信息

移动端以信息卡片的单列标签—内容布局展示，避免 Web 端“一行三列”在窄屏下截断内容。

| 字段名称 | 数据字段 | 展示规则 |
| --- | --- | --- |
| 施工时间 | `startAt` | 毫秒时间戳，格式 `YYYY-MM-DD HH:mm:ss`；无值显示 `--` |
| 项目名称 | `projectName` | 原样展示，长文本自动换行 |
| 施工内容 | `content` | 原样展示，长文本自动换行 |
| 施工面积 | `constructionArea` | 显示为 `{constructionArea}㎡`；无值显示 `--` |

### 3.2 建设 / 监理 / 施工方

以信息卡片展示参建单位与负责人。负责人姓名与手机号合并为两行展示；任一字段为空时只展示已有字段，均为空时显示 `--`。

| 字段名称 | 数据字段 |
| --- | --- |
| 建设方 | `fpuName` |
| 监理方 | `supervisionName` |
| 施工方 | `constructionName` |
| 建设方负责人 | `fpuOwnerName`、`fpuOwnerPhone` |
| 监理方负责人 | `supervisor`、`supervisorPhone` |
| 施工方负责人 | `constructorName`、`constructorPhone` |

### 3.3 关联资源

| 项目 | 规则 |
| --- | --- |
| 数据来源 | 详情接口的 `data.rooms` |
| 展示方式 | 资源卡片列表；每张卡片展示资源编号、资源名称、资源用途、二级单位和位置信息 |
| 资源用途 | `useType` 通过“资源类型映射”转换；未映射时展示原始值或 `--` |
| 空态 | `rooms` 为空、缺失或非数组时显示“暂无关联资源” |
| 资源跳转 | 原始需求未定义点击资源后的行为，本期只读展示，不跳转资源详情 |

资源卡片字段：

| 字段名称 | 数据字段 | 展示规则 |
| --- | --- | --- |
| 资源编号 | `roomNo` | 无值显示 `--` |
| 资源名称 | `roomName` | 无值显示 `--` |
| 资源用途 | `useType` | 通过映射接口转换 |
| 二级单位 | `fpuName` | 无值显示 `--` |
| 位置信息 | `address` | 无值显示 `--` |

### 3.4 附件资料

移动端使用纵向资料清单替代 Web 表格。每项资料展示资料名称、完整状态及关联附件数量；资料名称较长时自动换行。

#### 3.4.1 附件状态

| `fileStatus` | 文案 |
| --- | --- |
| `1` | 齐全 |
| `2` | 不齐全 |
| `0` | 不涉及 |

状态以 App 现有状态标签样式展示：齐全为成功态，不齐全为提示/错误态，不涉及为中性态。

#### 3.4.2 资料项组装规则

| 资料名称 | 状态字段 | 附件字段 |
| --- | --- | --- |
| 工程竣工验收报告 | `checkboxes1` | `accessory1` |
| 有关消防设施的工程竣工图纸 | `checkboxes2` | `accessory2` |
| 消防产品质量合格证明文件 | `checkboxes3` | `accessory3` |
| 关于燃烧性能的见证取样检验报告（附现场安装位置及现场照片） | `checkboxes4` | `accessory4` |
| 消防设施检测合格证明文件 | `checkboxes5` | `accessory5` |
| 施工、工程监理、检测单位的合法身份证明和资质等级证明文件 | `checkboxes6` | `accessory6` |
| 建设工程消防设计、验收备案凭证 | `checkboxes7` | `accessory7` |
| 法律、行政法规规定的其他材料 | `checkboxes8` | `accessory8` |
| 小微改造工程消防验收（备案）告知承诺管理回执 | `checkboxes9` | `accessory9` |
| 联合验收意见通知书 | `checkboxes9` | `accessory9` |
| 其他 | `checkboxes10` | `accessory10` |

面积条件：

- 当 `constructionArea < 300` 时，仅展示“小微改造工程消防验收（备案）告知承诺管理回执”。
- 当 `constructionArea >= 300` 时，仅展示“联合验收意见通知书”。
- 两项均使用 `checkboxes9`、`accessory9`，不可同时展示。

> 原始详情接口样例仅列出 `checkboxes1`～`checkboxes10` 和 `accessoryStatus`，未提供 `accessory1`～`accessory10` 的实际返回字段与文件对象结构。开发前必须补齐正常 JSON 样例后再确定附件数量、预览与下载实现。

## 4. 页面交互与状态

| 场景 | 行为 |
| --- | --- |
| 进入页面 | 以 `id` 请求详情；同时加载资源类型映射 |
| 点击返回 | 返回上一页，不修改施工档案数据 |
| 切换内容分段 | 仅切换当前内容区域，不重复请求详情接口 |
| 详情加载中 | 显示页面加载态，不展示其他记录的旧数据 |
| 详情请求失败 | 显示错误提示与“重新加载”入口 |
| 资源类型映射失败 | 不阻断详情展示，资源用途显示原始编码或 `--` |
| 关联资源为空 | 显示关联资源空态 |
| 附件资料为空或字段缺失 | 保留资料项与状态兜底；文件区域显示“暂无附件” |

附件点击后的预览、下载或外部打开方式，待接口文件对象结构与 App 文件组件能力确认后定义。

## 6. 数据容错规则

1. 时间字段仅在有效毫秒时间戳时格式化；否则显示 `--`。
2. `rooms` 非数组时按空数组处理，页面不得崩溃。
3. `constructionArea` 不可解析为数值时，不展示第 9 类面积条件资料项，避免错误显示两种互斥资料。
4. 附件状态不在 `0 / 1 / 2` 范围内时，显示 `--` 和中性标签。
5. 资料附件字段不存在、为空或格式异常时，显示“暂无附件”，不影响其他资料项和页面阅读。

## 7. 非目标

- 不在本页新增施工档案编辑、删除、审批或补充资料操作。
- 不调整施工档案详情接口和资源类型映射接口的后端契约。
- 不新增关联资源跳转，除非后续需求明确。
- 不自行假定附件对象结构、文件预览类型或下载策略。

## 8. 验收标准

1. 使用有效施工档案 `id` 可打开页面并展示任务信息和参建单位信息。
2. 关联资源按卡片列表展示，资源用途可正确映射；映射失败不影响其他内容。
3. 施工面积小于 300 与大于等于 300 时，第 9 类资料项分别且仅显示对应名称。
4. 附件资料可按 `checkboxes1`～`checkboxes10` 组装并展示正确状态。
5. 详情请求、映射请求、空资源和缺失附件均有稳定兜底，不白屏、不崩溃。
6. 页面不提供本期范围外的编辑、删除及状态变更操作。

## 9. 待确认项

1. 新页面的最终路由、目录位置和从“资源施工档案”列表进入详情的具体点击字段。
2. `accessory1`～`accessory10` 是否真实由详情接口返回；每个字段的完整 JSON 文件对象样例。
3. 附件资料项是否要根据 `accessoryStatus` 作为状态数据源，还是严格使用 `checkboxes1`～`checkboxes10`。
4. 附件是否支持 App 内预览、下载、分享或仅展示文件名与数量。
5. 建设方、监理方、施工方负责人的电话号码是否需要拨号交互。
