# 视频档案场景与本地上传分类整合设计

## 背景与目标

当前 `main` 含本地上传与分类功能，但不含提交 `376b7d843e5290d0ef39441b16a93e67c53fa205` 的三维档案场景。两条开发线从 `dc7d86a` 分叉，都修改了页面入口、场景、样式和界面测试。整合后的页面以该提交的浅色三维档案阵列、详情、检索、收藏、检视和动画为主体，同时保留当前本机上传、持久分类与即时刷新能力。

本次整合不改变上传 API、`documents/` 持久目录、元数据格式、文档转换和静态部署的能力边界；不删除或覆盖现有源文档。三维渲染不可用时，列表视图仍能筛选、上传、阅读和下载。

## 整合策略

从当前 `main` 建立整合分支，合入 `376b7d8` 所在分支，保留两条开发线的提交历史。以视频版 `ArchiveState`、`ArchiveSceneElement` 和 `ArchiveWorld` 作为场景基础，针对 Git 冲突和自动合并后可能出现的行为冲突逐项整合。`README.md`、依赖清单与两套测试需要合并语义，而非只选择其中一侧。构建产物及用户文档不参与冲突清理。

## 场景、分类与检索

- `src/main.ts` 持有完整清单、当前全局分类、当前选中文档的稳定 ID、上传面板及场景生命周期。`src/scene.ts` 接收完整清单、当前分类和控制回调；场景状态区分完整条目与当前可见条目，三维模型只为可见条目建立对象，目录检索与收藏仍使用完整条目。场景不接触磁盘或上传 HTTP 细节。
- 三维页面工具栏提供“全部”、实际分类和“未分类”的全局筛选。选项从完整清单生成，保持清单排序；选择后只显示匹配档案，数量、组别和方向导航基于可见集合更新，显示编号仍按完整清单的顺序计算，避免筛选后同一档案改号。无结果时显示空状态与返回“全部”的操作。空目录时仍显示可用的上传入口。
- 分类切换或清单刷新时，若原选中文档仍在可见集合中，继续选中其稳定 ID；否则选中该集合首项。当前分类已不存在时切回“全部”。重建场景时释放旧的 WebGL、动画、事件监听和弹层资源，避免重复渲染循环。
- 视频版档案目录的搜索与收藏仍面向完整清单，目录内分类筛选独立于全局筛选。从目录打开不在当前全局分类中的结果时，先切换到对应分类或“全部”，再按稳定 ID 定位并进入，不能打开错误文档。收藏继续用完整清单中的稳定 ID 存储，筛选和排序不会改变身份。
- 页面筛选控件、目录筛选、上传面板和简洁列表均可用键盘操作。三维动画、阅读、目录和上传面板各自保持正确的焦点与 `Esc` 行为；弹层打开时底层场景不可交互。

## 本机上传与刷新

- 仅当页面处于 `127.0.0.1` 且本机能力接口返回可用时，在新场景工具栏和空状态显示“上传档案”。纯静态站点不显示上传入口。上传组件沿用当前逐份提交、已有/新分类选择、成功失败反馈及 50 MiB 上限。
- 上传源文件仍进入 `documents/`，分类进入同名 `.meta.json`；服务器继续使用现有原子提交、冲突校验、预览生成和回滚流程。整合只调整前端入口和刷新协调，不另建存储。
- 面板保持打开且批量上传结束后重新读取清单，更新全局分类选项和三维场景，并尽量保留当前选中文档。新上传文档符合当前分类时即可通过场景或目录找到。刷新期间面板仍使场景不可交互，完成后恢复面板焦点。
- 上传中关闭面板时，当前请求可完成，但不再因该面板自动替换场景或中断后来打开的阅读器；后续文件不再提交。若面板已关闭，迟到的请求或刷新响应不得把场景留为 `inert`。其他清单刷新也遵守现有 generation 规则，不允许旧响应覆盖新场景。

## 文件边界

| 模块 | 整合后的职责 |
| --- | --- |
| `src/archive-state.ts`、`src/scene/*` | 区分完整条目与可见条目；模型只渲染可见集合，目录与收藏引用完整集合，按稳定 ID 恢复选择 |
| `src/scene.ts` | 三维和简洁列表界面、分类与上传入口、目录检索、收藏及资源释放 |
| `src/main.ts` | 完整清单、全局分类、上传能力、刷新、阅读器及弹层生命周期 |
| `src/categories.ts`、`src/upload.ts` | 分类规范化与筛选；文件选择、逐份提交和反馈 |
| `scripts/local-upload.mjs`、`scripts/build-archive.mjs`、`vite.config.ts` | 保持已验证的本机上传、持久化和增量发布逻辑 |
| `src/style.css`、`README.md` | 新场景中的控件样式和合并后的使用说明 |

## 验收

1. 视频版的阵列、动画、详情、检索、收藏、360° 检视、阅读和下载仍可用；WebGL 不可用时可在简洁视图完成核心操作。
2. 本机开发和预览服务可上传四种支持格式；文件与分类保存到 `documents/`，无需重启即可出现在三维场景和目录中；静态站点只提供浏览与筛选。
3. 全局分类、目录检索和收藏在筛选、上传与刷新后保持正确文档身份；空分类、无结果和已删除分类有明确处理。
4. 上传面板关闭、阅读器打开、目录弹层打开及快速刷新交错发生时，不留下不可操作场景、重复事件监听或中断后的错误焦点。
5. 合并两边测试并补交互回归；完整测试、TypeScript 与生产构建通过。用实际浏览器检查宽屏、窄屏、上传、分类和回退视图，不以单张静态截图代替动画验收。

## 风险与处理

Git 可以自动合并大部分源文件，却不能证明两套 `renderScene` 调用与生命周期相容。以行为测试覆盖接口整合和弹层交错。三维场景重建可能触发资源泄漏或开场动画重播，应确保 `dispose()` 完整释放并在普通筛选/上传刷新时维持合理的入场状态。合并 `three`、`@types/three` 与 `busboy` 依赖时以锁文件一致性和干净安装验证。服务器写入权限继续限制在本机回环接口，既有大小与同名保护保持不变。
