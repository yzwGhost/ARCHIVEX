# 档案与分类删除、回收和抽离动画设计

## 目标与范围

本机档案馆允许删除单份档案，或删除一个分类及其中全部档案。服务端成功回收后，页面播放抽离动画并更新阵列；原件与元数据进入可恢复的本地回收区，重启服务或重新构建不会让它们重新出现。单份删除呈现档案从所在分类排被抽走的动画；批量删除呈现该排档案依次抽离。支持桌面、窄屏和 WebGL 不可用时的简洁视图。

本次不提供永久清空回收区、分类改名、跨分类移动、账号或远程同步。纯静态部署保持只读，不出现管理入口。现有上传、阅读、检索、收藏、分类导航和空白档案填充行为继续工作。

## 方案选择

页面隐藏档案会在重新构建时从 `documents/` 再次读出。直接永久删除原件则没有应用内恢复途径。采用项目内、`documents/` 外的 `.archive-trash/` 作为回收区，并加入 `.gitignore`。源文件仍以 `documents/` 为唯一在架目录；`public/archive/` 和 `dist/archive/` 只包含可重建的发布副本。

分类不是独立记录，而是从清单中档案的 `category` 值生成。因此“删除分类”以当前清单中属于该分类的全部稳定档案 ID 为一个批次，将这些原件移入回收区。`未分类` 是系统默认名称，不提供“删除分类”操作；提供措辞明确的“清空未分类”，同样批量回收其档案。

## 界面与交互

- 档案详情页增加“删除档案”操作；按钮与下载、收藏区风格一致，使用 Lucide 图标。确认弹框显示档案名称和“移入回收区，可恢复”，取消是默认焦点。
- 工具栏增加“管理分类”入口。列表显示分类名称、档案数量和删除操作。确认弹框显示分类名称、数量，并明确说明分类内所有档案一起移入回收区。
- 工具栏增加“回收区”入口，列出单份与分类批次，显示原名称、删除时间、档案数量和“恢复”。恢复到原来的 `documents/` 路径；目标已存在时返回冲突，不覆盖现有原件或元数据。分类批次恢复后，分类由恢复的档案自然重新出现。
- 弹框与回收区遵循现有焦点圈定、`Esc` 关闭和底层 `inert` 规则。删除或恢复请求处理中禁用重复提交，展示状态和明确错误；失败时保留当前场景。
- 删除后按最新清单重建场景。单份删除时选择同排邻近档案；该排无档案时选择最近的分类排。当前分类已消失则切回“全部”。其余档案的稳定 ID 不变，显示编号可随完整清单重新排列；失效收藏在重载时清理。恢复后尽量定位原档案。

## 抽离动画

服务端成功回收后才播放动画；数据操作失败时不播放。动画期间保留旧场景和旧清单供渲染，锁定方向键、点击、弹层与重复删除，完成后才读取新清单并重建阵列。

单份删除从档案所在排开始。若当前在详情页，镜头先平滑回到该排；目标档案随后沿档案正面方向滑出，略微抬起、轻微倾斜，最后移出视野。原位短暂留空，随后新阵列按现有布局补入空白档案。分类删除先让目标分类排进入视野，再使该排当前可见的档案以短间隔依次抽离，控制总时长，最后更新分类排布。动画由 `ArchiveWorld` 为目标模型维护独立位移值；不改变共享材质，避免其他档案一起变色或透明。

启用系统“减少动态效果”时跳过抽离和镜头运动，直接更新场景。WebGL 不可用时，简洁列表以短暂的行移出效果替代。页面切换、组件释放或 WebGL 上下文丢失会结束等待并读取最新清单，不让界面停在锁定状态。

## 本机接口与数据一致性

- 在现有 Vite 开发及预览中间件增加单份回收、分类批量回收、列出回收区、恢复接口；继续只监听 `127.0.0.1`，核验同源请求，静态站点无接口。客户端传稳定 ID 或分类名，服务端必须从当前清单解析原路径与成员，不能直接接受客户端提供的磁盘路径。
- 上传、删除、恢复共用串行写入队列。单份删除和分类删除先校验全部成员及文件路径位于 `documents/`，拒绝符号链接、junction、路径穿越及不一致的清单。分类批次以请求开始时的清单为准，在队列内重新核验成员，避免与上传竞争。
- `.archive-trash/` 以操作 ID 保存原相对路径、原件、相关 `.meta.json` 及批次记录。若同目录有不同扩展名但同 stem 的档案共享元数据，删除其中一份不能移走仍被其他在架档案使用的元数据；回收区保留其快照。恢复时若共享元数据仍与快照一致，可以复用；若内容已变则报冲突，绝不覆盖。分类批次中的共享元数据只移动一次。
- 事务先写批次记录并暂存文件，再原子替换 `manifest.json`；同时移走生成的原件副本和预览，保证旧 URL 不继续暴露已删除档案。中途失败回滚文件和清单。启动时检查未完成批次，并依据提交状态恢复或完成操作，避免进程中断造成源文件失联。
- 恢复时对整个批次预检所有目标。任一原路径或元数据目标冲突时不恢复该批次、不覆盖现有文件；成功后复用现有生成逻辑发布档案、原件副本、预览和新清单。回收区不自动清空。

## 模块边界

| 模块 | 职责 |
| --- | --- |
| `scripts/local-upload.mjs` 或拆出的本机管理模块 | 共用同源校验、串行队列、回收与恢复请求 |
| `scripts/build-archive.mjs` | 清单及发布文件的增量移除、恢复发布和安全校验 |
| `src/main.ts` | 管理能力、请求与场景刷新协调、选择和弹层生命周期 |
| `src/scene.ts`、新增回收区/确认组件 | 入口、确认、列表及简洁视图反馈 |
| `src/scene/ArchiveWorld.ts` | 按稳定 ID 播放可取消的单份或批量抽离动画 |
| `src/style.css`、`src/types.ts`、`README.md` | 视觉、接口类型与使用说明 |

## 验收与风险

1. 单份与分类删除后，页面、源目录和生成清单同步；重启及完整构建后不会重现。回收区恢复保留原路径与可用预览。
2. 原件、元数据、预览、清单任何一步失败均不留下半删除状态；共享元数据、嵌套路径、同名冲突、符号链接与批量中断有覆盖测试。
3. 删除与上传并发时结果确定；快速切换场景、关闭弹框、阅读器打开或 WebGL 降级时不残留锁定、重复动画或错误焦点。
4. 宽屏、窄屏实测抽离方向、相邻档案不受影响、批量动画总时长、空白档案补位以及减少动态效果。键盘上下切分类、左右切档案仍可用。
5. 回收区保存原始档案，可能占用额外空间；不自动清空以免意外丢失，用户可在项目目录内自行备份。
