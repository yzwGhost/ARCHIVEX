# V2.2.9 人员详情（App）

## 1. 需求概述

为 App 新增人员只读详情页，供用户查看单位人员的基本资料，以及消防考试、消防演练、消防培训三类档案。

本需求由 Web 端《人员详情》转换而来。移动端使用原生导航页、信息卡片和纵向滚动列表替代 Web 端的 `FullScreenModal`、`ProDescription` 与表格；本期仅覆盖查看，不新增人员资料和档案的编辑、删除或新增能力。

## 2. 页面信息

| 项目 | 说明 |
| --- | --- |
| 页面名称 | 人员详情 |
| 推荐页面目录 | `src/app/screens-v2/danweirenyuan/PersonnelDetail/`（待实现） |
| 路由建议 | `/danweirenyuan/PersonnelDetail?id=:id`（待确认） |
| 入参 | `id`：`fpu_user` 记录 ID，必填 |
| 档案查询入参 | 详情返回的 `userId`，必填；不得误用页面路由 `id` |
| 页面标题 | 人员详情 |
| 参考结构 | `ChannelHeader + ScrollView + Panel + TabWrap/ListV2` 的只读详情页结构 |

### 2.1 页面结构

1. 顶部导航栏：显示返回按钮与“人员详情”标题。
2. 基本信息区：使用信息卡片展示姓名、联系方式、一级单位、二级单位、角色。
3. 档案区：使用 `TabWrap` 展示“消防考试档案”“消防演练档案”“消防培训档案”三个 Tab；每个 Tab 为独立分页列表。
4. 本期不配置编辑、删除或新增档案的底部操作按钮。

> 页面进入时仅加载人员详情与角色映射；切换到某个档案 Tab 后，才加载该 Tab 的第 1 页，避免首次进入同时发起三类档案查询。

## 5. 页面交互与状态

| 场景 | 行为 |
| --- | --- |
| 进入页面 | 校验路由 `id`；有效时请求人员详情和角色映射。详情返回有效 `userId` 后，档案 Tab 才可查询 |
| 点击返回 | 返回上一页，不修改人员或档案数据 |
| 切换 Tab | 仅切换内容区域；首次进入目标 Tab 时加载第一页，已加载数据保留 |
| 下拉刷新 | 刷新当前 Tab 的数据；基本信息不因档案下拉刷新而重复请求 |
| 加载更多 | 演练、培训档案按各自分页契约加载下一页；考试档案在分页契约确认前不展示加载更多 |
| 详情加载中 | 显示页面加载态，不展示上一个人员的旧数据 |
| 详情请求失败 | 显示稳定错误态与“重新加载”入口；不请求档案列表 |
| 枚举映射请求失败 | 不阻断详情和档案展示；相关字段回退原始编码或 `--` |
| 档案请求失败 | 仅当前 Tab 显示错误态与重试入口，不影响基本信息和其他 Tab |
| 空数据 | 人员详情字段按 `--` 展示；各档案 Tab 使用各自空态文案 |

## 6. 接口与字段处理

> 以下接口路径、方法与字段沿用原 PRD。App 实现时必须通过 Adapter → Service → Store → UI 分层调用，页面和列表组件不得直接请求接口或解析 HTTP 响应。

### 6.1 角色映射

| 项目 | 说明 |
| --- | --- |
| 接口 | `GET /api/v2/metadata/fpu_user/fields?field=roleType` |
| 用途 | 将基本信息中的 `roleType` 转换为角色文案 |
| 返回处理 | 读取 `data` 数组中的 `label`、`value`；映射缺失不阻断详情展示 |

正常返回示例：

```json
{
  "status": 0,
  "msg": "success",
  "data": [{ "label": "单位管理员", "value": 1 }]
}
```

### 6.2 考试结果映射

| 项目 | 说明 |
| --- | --- |
| 接口 | `GET /api/v2/metadata/exam_paper_user/fields?field=isPass` |
| 用途 | 将考试档案中的 `isPass` 转换为考试结果文案 |
| 返回处理 | 读取 `data` 数组中的 `label`、`value`；映射缺失不阻断考试档案展示 |

正常返回示例：

{

### 6.3 消防考试档案

| 项目 | 说明 |
| --- | --- |
| 接口 | `POST /api/data/v2/examination/queryExamListByUser` |
| 必填参数 | `userId`：人员详情接口返回的用户 ID |
| 用途 | 获取该人员的消防考试档案 |
| 已知返回 | 原 PRD 仅说明 `data: any[]`，未提供正常字段样例与分页信息 |
| 必要字段 | `paperName`、`passTime`、`results`、`useTime`、`isPass` |
| 响应处理 | 返回数据缺失、非数组或关键字段格式异常时进入稳定空态/错误态，不得导致页面崩溃 |

### 6.6 消防演练档案列表

| 项目 | 说明 |
| --- | --- |

### 6.7 消防培训档案

| 项目 | 说明 |
| --- | --- |
| 接口 | `POST /api/data/v2/objects/training_user/query` |
| 用途 | 获取该人员的消防培训档案 |
| 固定参数 | `objectApiKey=training_user`；`orderBy=createdAt`；`orderDir=desc` |

## 7. App 数据分层与行为追踪

### 7.1 数据分层

| 层级 | 职责 |
| --- | --- |
| Adapter | 校验人员详情、三类档案和枚举映射响应；解析失败时返回包含 `apiKey`、字段路径与追踪信息的错误 |
| Service | 唯一业务请求入口，向 Store 返回 `Result<T>` |
| Store | 管理详情、映射、三个档案列表各自的加载、分页、空态和错误状态；不直接依赖 UI |
| UI | 只读取 Store 或向 `ListV2` 注入 loader，不直接调用 `fetch` 或解析接口数据 |

### 7.2 主流程埋点

| 场景 | trackTarget | trackExtra |
| --- | --- | --- |
| 切换考试档案 Tab | `danweirenyuan.personnel-detail.tab.exam.switch` | `id` |
| 切换演练档案 Tab | `danweirenyuan.personnel-detail.tab.drill.switch` | `id` |
| 切换培训档案 Tab | `danweirenyuan.personnel-detail.tab.training.switch` | `id` |
| 重试详情加载 | `danweirenyuan.personnel-detail.retry` | `id` |
| 重试考试档案加载 | `danweirenyuan.personnel-detail.exam.retry` | `id`、`userId` |
| 重试演练档案加载 | `danweirenyuan.personnel-detail.drill.retry` | `id`、`userId` |
| 重试培训档案加载 | `danweirenyuan.personnel-detail.training.retry` | `id`、`userId` |

## 8. 非目标

- 不新增人员资料的创建、编辑、删除、角色分配或单位调整能力。
- 不新增考试、演练、培训档案的创建、编辑、删除、报名或详情跳转。
- 不修改 `fpu_user`、考试、演练、培训和元数据映射接口的后端契约。
- 不调整 Web 端的 `FullScreenModal`、表格或筛选交互。

## 9. 验收标准

1. 传入有效人员 `id` 可进入详情页并展示基本信息；缺失、非法 ID 或详情请求失败时页面有稳定错误态和重试入口。
2. 角色、考试结果、演练类别和演练结果评估可正确映射；任一映射接口失败不影响基本信息和档案主体展示。
3. 三类档案均按需加载，切换已加载 Tab 不重复请求首屏数据；某一 Tab 请求失败不影响其他 Tab。
4. 演练和培训档案支持分页、下拉刷新、空态和错误重试；考试档案待分页契约确认后按约定实现对应行为。
5. 所有时间字段按 `YYYY-MM-DD HH:mm:ss` 展示，`useTime` 可正确从毫秒转换为 `HH:mm:ss`；空值与异常值不导致页面崩溃。
6. 培训档案的 `items` 缺失或非数组、详情缺少 `userId`、枚举未命中等异常均有稳定兜底，不白屏、不渲染上一名人员的旧数据。
7. 新增主动点击入口均使用 `BehaviorTouchable` 或带 `trackTarget` 的 `Button`，且动态 `id` 不拼入 `trackTarget`。

## 10. 待确认项

1. 人员详情的最终路由、菜单入口及归属模块是否采用本文建议的 `/danweirenyuan/PersonnelDetail`。
2. 原始人员详情示例未返回 `userPhone`，但字段表要求展示；需确认服务端实际字段是否稳定提供。
3. 消防考试档案接口的正常 JSON 样例、是否分页、分页请求参数及响应总数结构尚未提供。
4. 消防演练档案列表接口的分页响应结构尚未提供；需确认是否返回 `items/count`，或采用其他总数/游标字段。
5. `drillType` 在原 PRD 中标注为“演练类别”；需确认其最终中文业务语义，避免与其他演练页面的“演练类型”混淆。
6. `trainingResult` 是否为枚举编码、对应的映射接口及未映射回退文案尚未提供。
7. 三个 Tab 的默认 `perPage` 值、是否显示筛选入口，以及考试档案是否允许加载更多，待 UI 与后端联调确认。
