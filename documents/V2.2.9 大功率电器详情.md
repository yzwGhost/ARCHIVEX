# V2.2.9 大功率电器详情（App）

## 1. 需求概述

为 App 提供大功率电器只读详情页，供用户查看设备基本信息、设备图片、维护记录及编辑记录。

本需求由 Web 端《大功率电器详情》转换而来。移动端使用原生导航页、信息卡片、图片分组和纵向分页列表替代 Web 端的描述组件与表格；本期仅支持查看，不新增设备维护、编辑、删除、审批或图片上传能力。

| 路由建议 | `/dagonglvdianqi/HighPowerApplianceDetail?id=:id`（待确认） |
| 入参 | `id`：大功率电器 ID，必填 |
| 页面标题 | 大功率电器详情 |
| 存量参考 | `src/app/screens/RoomEquipment/Detail/`；仅可复用展示与入口经验，数据层需按 Adapter → Service → Store → UI 实现 |

### 2.1 页面结构

1. 顶部导航栏：显示返回按钮与“大功率电器详情”标题。
2. 基本信息：使用纵向信息卡片展示设备资料，长文本自动换行。
3. 内容 Tab：`图片`、`维护记录`、`编辑记录`。图片 Tab 展示六类图片分组；两个记录 Tab 使用独立的 `ListV2` 分页列表。
4. 本期不配置底部操作按钮。

> 页面进入时加载设备详情及必要枚举映射；首次切换到维护记录或编辑记录 Tab 时加载该 Tab 的第一页，避免首次进入并发请求所有分页数据。

## 4. 内容 Tab

### 4.1 图片

图片 Tab 使用图片分组卡片展示以下字段；每张图片以缩略图呈现，点击后调用 App 既有图片预览能力。空图片组展示 `暂无图片`，单张图片加载失败仅显示占位，不影响其他信息。

| 分组名称 | 数据字段 |
| --- | --- |
| 现场设备照片 | `localEquipmentImg` |
| 制度上墙照片 | `localRequireImg` |
| 铭牌照片 | `nameplateImg` |
| 产品认证 | `approvedImg` |
| 产品合格证 | `certificate` |
| 贴签照片 | `tagImg` |

> 各图片字段的最终类型（URL 字符串、URL 数组、文件对象数组或 JSON 字符串）由详情接口正常样例确认。实现时必须先容错规范化为可预览图片数组，禁止在 UI 直接解析原始 JSON。

## 5. 页面交互与状态

| 场景 | 行为 |
| --- | --- |
| 进入页面 | 校验路由 `id`；有效时加载详情及三类映射；非法或缺失时显示稳定错误态 |
| 点击返回 | 返回上一页，不修改设备数据 |
| 切换 Tab | 仅切换内容区域；首次进入记录 Tab 时加载第一页，已加载的记录数据保留 |
| 点击图片 | 调用既有图片预览；图片地址不可访问时显示占位 |
| 下拉刷新 | 刷新当前记录 Tab；详情与其他 Tab 不重复请求 |
| 加载更多 | 当前记录 Tab 按自身分页状态加载下一页 |
| 详情请求失败 | 显示“加载失败”和“重新加载”入口；不展示上一个设备的旧数据 |
| 映射请求失败 | 不阻断详情展示；字段回退原始编码或 `--` |
| 记录请求失败 | 仅当前 Tab 显示错误态与重试入口，不影响基本信息及其他 Tab |

## 6. 接口与字段处理

> 以下路径、方法及字段沿用原 PRD。App 实现时由 Adapter 校验响应、Service 作为唯一网络入口、Store 管理详情与分页状态，UI 不直接调用 `fetch` 或解析原始响应。

### 6.1 大功率电器详情

| 项目 | 说明 |
| --- | --- |
| 接口 | `GET /api/data/v2/roomEquipment/detail` |
| 请求参数 | `id`：页面路由入参，大功率电器 ID |
| 用途 | 获取基本信息与图片 Tab 的全部字段 |
| 已知返回 | 原 PRD 仅说明 `data: any`，未提供正常 JSON 样例 |
| 必要字段 | 第 3 节基础字段及第 4.1 节六类图片字段 |
| 响应处理 | `data` 缺失、`id` 非法或图片字段格式不符合契约时，页面不得白屏；详情缺失时显示稳定错误态 |

### 6.2 分类映射

| 项目 | 说明 |
| --- | --- |
| 接口 | `GET /api/v2/metadata/room_equipment/fields?field=category` |
| 用途 | 将 `category` 转换为分类文案 |
| 返回处理 | 读取 `data` 数组的 `label`、`value`；映射缺失不阻断详情展示 |

正常返回示例：

```json
{ "status": 0, "msg": "success", "data": [{ "label": "厨房设备", "value": 1 }] }
```

### 6.5 维护记录

## 7. App 数据分层与行为追踪

### 7.1 数据分层

| 层级 | 职责 |
| --- | --- |
| Adapter | 校验详情、三类枚举映射和两个记录列表响应；解析失败时产生包含 `apiKey`、字段路径与追踪信息的错误 |
| Service | 唯一业务请求入口，向 Store 返回 `Result<T>` |
| Store | 管理详情、映射、图片规范化、两个记录列表的加载/分页/错误状态；仅调用 Service |
| UI | 只读取 Store 或向 `ListV2` 注入 loader；不直接调用 `fetch` 或解析 HTTP 数据 |

## 8. 非目标

- 不新增大功率电器的创建、编辑、删除、审批、贴签或状态变更能力。
- 不新增维护记录、编辑记录的新增、修改、删除或附件操作。
- 不修改详情、元数据映射和两类日志接口的后端契约。
- 不调整 Web 端页面、表格或筛选交互。

## 9. 验收标准

1. 有效设备 `id` 可进入详情页并展示基础字段；缺失、非法 ID 或详情请求失败时有稳定错误态与重试入口。
2. 分类、能耗等级和维护周期可正确映射；任一映射请求失败不影响详情其他字段的查看。
3. 六类图片均可展示多图、空图与加载失败状态；可访问图片支持预览且不会影响其他图片组。
4. 维护记录和编辑记录可独立按页加载、下拉刷新、显示空态和错误重试；一方失败不影响另一方及基本信息。
5. 全部日期字段按 `YYYY-MM-DD HH:mm:ss` 展示；空值、无效时间和未知状态均不会造成白屏或崩溃。
6. 新增主动点击入口均使用 `BehaviorTouchable` 或带 `trackTarget` 的 `Button`，且动态 ID 不拼入 `trackTarget`。

## 10. 待确认项

1. 最终入口是复用存量 `/RoomEquipment/Detail?id=:id`，还是采用本文建议的新 `screens-v2` 路由；若新建，资源详情“电器列表”的查看详情按钮需同步接线。
2. 详情接口的正常 JSON 样例及所有图片字段的实际数据类型尚未提供，特别是单图/多图、文件对象、JSON 字符串及空值格式。
3. `category` 在原 PRD 中备注为“品牌映射”，但字段名称是“分类”；本文按“分类映射”处理，需产品/后端确认最终语义。
4. `energyConsumption`、`maintenanceCycle` 映射接口是否应从 `room_equipment_apply` 获取，需以后端实际元数据配置为准。
5. 维护记录和编辑记录的默认 `perPage` 值、是否需要搜索/筛选，以及时间字段的服务端排序规则待联调确认。
