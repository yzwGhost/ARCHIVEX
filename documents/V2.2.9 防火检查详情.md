# V2.2.9 防火检查详情（App）

## 1. 需求概述

为 App 中的防火检查工单提供只读详情页，便于现场人员查看工单基本信息、已完成的检查内容、任务流转记录及修复记录。

本需求由 Web 端《V2.2.9 防火检查详情》转换而来。移动端遵循现有工单页面的导航、信息卡片和纵向滚动模式；本期仅覆盖详情查看，不新增处理、审批、删除等工单操作。

## 2. 页面信息

| 项目 | 说明 |
| --- | --- |
| 页面名称 | 防火检查详情 |
| 推荐页面实现 | `src/app/screens/WorkSheet/Room/RoomDetail.tsx` 的只读详情能力；如需独立页面，应复用其页面结构与工单详情数据来源 |
| 路由参考 | `/WorkSheet/Room/RoomDetail?worksheetId=:id` |
| 入参 | `worksheetId`：防火检查工单 ID，必填 |
| 工单类型 | `ruhujianchagongdan` |
| 页面标题 | 防火检查详情 |

### 2.1 页面结构

页面采用 `SafeScreenView + Head + ScrollView` 的标准移动端布局：

1. 顶部导航栏：显示返回按钮和“防火检查详情”标题。
2. 基本信息卡片：展示工单核心信息，两列标签—内容布局；长文本自动换行。
3. 内容分段：使用 App 现有 `TabWrap`，支持左右滑动切换；每个 Tab 内独立纵向滚动。
4. 页面不配置底部操作按钮。本期只读。

> 移动端不使用 Web 的 `FullScreenModal` 和 `ProDescription`；以原生导航页和信息卡片替代。

### 2.2 基本信息

| 字段名称 | 数据字段 | 展示规则 |
| --- | --- | --- |
| 任务编号 | `data.name` | 原样展示 |
| 创建时间 | `data.createdAt` | 毫秒时间戳，格式 `YYYY-MM-DD HH:mm:ss`；无值显示 `--` |
| 资源号 | `data.roomNo` | 无值显示 `--` |
| 空间位置 | `data.building`、`data.floor`、`data.area` | 由“位置信息映射”获取名称，按 `building / floor / area` 拼接；缺失层级不展示对应分隔符 |
| 资源用途 | `data.useType` | 由“资源用途映射”转换；未映射时显示原值或 `--` |
| 所属计划 | `data.planName` | 无值显示 `--` |
| 计划完成时间 | `data.expectFinishAt` | 毫秒时间戳，格式 `YYYY-MM-DD HH:mm:ss`；无值显示 `--` |

## 3. 内容 Tab

### 3.1 检查内容

| 项目 | 规则 |
| --- | --- |
| 显示条件 | 仅当工单 `data.status === 900`（已完成）时显示该 Tab |
| 数据来源 | `data.details[0].operContent` |
| 数据处理 | 使用 `tryJsonParse(operContent, [])` 解析；解析失败或结果非数组时按空数据处理，页面不得崩溃 |
| 展示方式 | 复用现有 `TemplateWrap` 的只读样式：按检查分组展示检查项、选项结果、填写内容、图片及异常说明 |
| 空态 | 已完成但无有效检查内容时，显示“暂无检查内容” |

`operContent` 中的检查分组和检查项结构以接口实际返回为准，正常样例见第 5.3 节。

### 3.2 任务进度

| 项目 | 规则 |
| --- | --- |
| 显示条件 | 始终显示 |
| 数据来源 | `data.nodes` |
| 展示方式 | 使用 App 既有的时间线展示模式（`WorkTimeLine`）；按接口返回顺序展示 `operTitle`、`name`、`createdAt`、`content` 及 `node` 扩展字段 |
| 时间格式 | `createdAt` 按 `YYYY-MM-DD HH:mm:ss` 展示 |
| 空态 | 无节点时显示“暂无任务进度” |

### 3.3 修复进度

| 项目 | 规则 |
| --- | --- |
| 显示条件 | `data.details[0].reviewContent` 解析后为非空数组时显示；无值、空数组或解析失败时不显示该 Tab |
| 数据来源 | `data.details[0].reviewContent` |
| 数据处理 | 使用 `tryJsonParse(reviewContent, [])` 解析 |
| 展示内容 | 按时间线展示 `subject`、`reviewResult`、`acceptResult`、`acceptContent`、`reviewTime`、`acceptTime` 与签名图片 `cfrOwnerSign.url`（如有） |
| 时间规则 | 同一条记录优先显示 `acceptTime`，无 `acceptTime` 时显示 `reviewTime` |

> `reviewContent` 的时间线视觉样式需在开发时与现有 `WorkTimeLine` 的字段适配确认；本 PRD 仅定义数据和显示规则。

## 4. 页面交互与状态

| 场景 | 行为 |
| --- | --- |
| 进入页面 | 使用 `worksheetId` 请求工单详情，并同时准备位置、资源用途映射数据 |
| 点击返回 | 返回上一页；不修改工单数据 |
| 切换 Tab | 仅切换当前内容区域，不重复请求详情接口 |
| 首次展示 Tab | 工单已完成且存在检查内容时默认“检查内容”；否则默认“任务进度” |
| 加载中 | 显示页面加载态，不展示旧工单数据 |
| 详情请求失败 | 显示错误提示和“重新加载”入口 |
| 映射请求失败 | 不阻断详情展示；空间位置/资源用途按原始编码或 `--` 兜底 |

## 6. 数据与展示规则

1. `details` 为空时，检查内容按空态处理，修复进度 Tab 不显示。
2. `operContent`、`reviewContent` 均为 JSON 字符串，必须容错解析，不能直接 `JSON.parse` 后无保护渲染。
3. 图片字段为空、地址失效或加载失败时，展示图片占位/加载失败态，不影响其他内容阅读。
4. `nodes`、`reviewContent` 的服务端排序不在本期重排；按接口返回顺序展示。
5. 映射值优先使用完整层级键：`building|floor|area`；找不到时依次回退到已有层级名称或编码。

## 7. 非目标

- 不在本页面新增工单处理、审批、重新派单、删除或签名操作。
- 不修改防火检查模板、检查项录入规则或修复流程。
- 不调整详情接口、位置映射接口和资源用途映射接口的后端契约。

## 8. 验收标准

1. 通过有效 `worksheetId` 可进入页面并完整展示基本信息。
2. 位置和资源用途能正确映射；映射失败时详情页仍可用。
3. `status === 900` 时可查看解析后的检查内容；其他状态不显示该 Tab。
4. 任务进度可展示 `nodes` 中的操作、人员、时间和内容。
5. 有效且非空的 `reviewContent` 才展示修复进度；无值或解析失败不展示该 Tab。
6. 接口请求、JSON 解析、图片加载异常均有稳定兜底，不导致白屏或崩溃。

## 9. 待确认项

1. 防火检查详情的最终入口是否统一使用现有 `/WorkSheet/Room/RoomDetail`，还是需要新增独立路由。
2. `status === 900` 以外的完成态是否也需要展示“检查内容”。当前严格沿用原 PRD 的 `900` 条件。
3. 修复进度是否需要完整复用 Web 的 `FlowLine` 字段与视觉样式，或以 App 现有 `WorkTimeLine` 样式呈现。
4. 检查内容中的图片点击后是否需要全屏预览，以及签名图片的查看交互。
