# V2.2.11 维保管理工作台：APP 页面生成需求

> 状态：APP 设计稿已审核通过；本文件仍为 OpenSpec 阶段 A 的页面生成输入稿，接口契约待确认。不构成已评审的 `proposal.md`、`design.md` 或 `tasks.md`。
>
> 来源：仓库外的《APP端-维保管理工作台_PRD.md》（V1.0.0，草稿）、同目录《Web端-维保管理工作台_PRD.md》及 APP 原型 `原型/维保工作台-APP端.html`。实际文件路径见文末。

## 1. 生成目标与边界

面向 APP 端维保员，提供「看待办 → 进工单列表 → 打开既有处置页」和「看年度进度 → 下钻设备类型、周期与任务」两条流程。页面数字只显示当前租户、当前用户可见范围内的数据；「全部」仍受用户岗位与设备岗位交集约束，区域不参与权限过滤。权限与统计计算由后端契约承载，页面不得自行扩大可见范围或重新计算进度与逾期状态。

本次页面范围：业务中心入口、维保工作台二级页（维保任务／维保跟踪）、复用的维保工单任务页、独立的逾期未完成工单列表、全年维保完成详情、系统维保详情、任务明细清单。工单执行跳转到现有处置页。

不生成：工单执行表单、审批、故障任务视图、历史统计、探测类触发式维保、计划外维保、Web 页面。

**生成阶段约束**：接口未确定时，可生成真实布局、受控筛选状态、空态／加载／错误态及明确标记的演示数据；不得编造接口地址、`apiKey`、响应字段或业务计算公式。接口确认并提供正常及异常 JSON 样例后，才进入 Adapter → Service → Store → UI 的数据接入与 OpenSpec 后续 Gate。

## 3. 页面规格

### P0 业务中心入口

- 展示业务卡标题「维保业务」、副标题「维保任务与进度跟踪」。整卡点击进入 P1。
- 入口可见性由现有业务中心权限体系决定；权限配置与实际入口位置待确认。

### P1-A 维保任务 Tab

| 区块 | 展示字段／规则 | 操作 |
|---|---|---|
| 完成工单卡 | 统计日标题（10:00 前「昨日完成工单」、此后「今日完成工单」）、统计日期、总数、个人数；卡底固定「每日 10:00 前统计昨日数据」 | 整卡进入 P4 |
| 逾期未完成工单卡 | 登录人可见范围内的逾期未完成单数；卡片视觉沿用 `src/app/screens-v2/weihubaoyang/Components/ListCard.tsx` 的白底、圆角、标题／次级信息、分隔线与内容区结构，保留工作台统计卡语义 | 整卡进入 P3 |
| 各系统待办任务 | 「我的／全部」分段切换；仅有在办任务的系统出卡；每卡显示系统名、剩余数、统计日完成数及「昨日完成／今日完成」标签 | 切换后重载系统卡；整卡进入 P2 |

- 「我的」为派给本人的任务；「全部」为本人数据权限可见范围。切换时卡片和数字同步更新。
- 完成卡总数与系统完成数、P4 当日档未筛选总数应同源。逾期单包含在剩余数内。若接口分别返回这些数据，须在联调时核对相等关系。
- 统计日以服务端时间判断：服务端时间早于 10:00 取昨日，否则取今日。随既有每 5 分钟数据同步重新判定，最迟 10:05 更新；页面不另设定时器。前端使用服务端返回的统计日／窗口或已确认的同步机制，不能用本机时间替代。
- 「我的」无在办任务时显示区块空态；某系统无在办任务时不出卡。

### P1-B 维保跟踪 Tab

| 区块 | 展示字段／规则 | 操作 |
|---|---|---|
| 年度选择 | 标题「各系统全年维保进度」右侧分段控件「今年／去年」，默认今年 | 切换后重载本 Tab 系统卡；P5／P6 继承年度 |
| 系统进度卡 | 系统名、应维保设备总数、实际进度、建议进度、填充进度条与建议基线 | 整卡进入 P5 |
| 提示区 | 有滞后类型时列「进度滞后」及类型名；有历史遗漏时列「历史遗漏」及单数；两项都无则隐藏 | 历史遗漏整行进入系统级 P6 |

- 本 Tab 不显示汇总卡与任务数。系统卡本体不因滞后变色；实际进度低于建议进度时，进度条填充使用警示色。提示区文案按 Web PRD §4.5.5：滞后类型不超过 2 个时列全名，达到 3 个时列前两个加「等 N 个类型」。
- 只展示所选年度有维保计划的系统，按消防系统主数据编码升序；「其他」不单独出卡。无计划时显示「暂无维保计划数据」。
- 今年以服务端今日为基准；去年按去年 12 月 31 日回算。应维保设备数取当前台账。计算与滞后判定以 Web PRD §4.5.4、年度规则以其 §4.5.6 为准，不在页面重算。
- 在 P5／P6 往返时保持年度；重新进入 P1 时恢复今年。年度不影响任务 Tab、P2、P3、P4。

### P2 维保工单任务（已确认复用）

- 工作台系统卡进入现有 `src/app/screens-v2/weihubaoyang/MaintainList`，不新生成一套维保工单列表。该页现有 Tab 为「全部／待办／已办／我发起的」，搜索占位为「搜索位置、任务编号、设备编号」，筛选含系统类型、计划名称、流程状态、创建时间及任务是否逾期。
- 现有 `WeibaoList` 使用现有 `ListCard`，卡片当前展示设备类型、状态、消防系统、创建时间、位置、任务编号、所属计划、设备编码；点击进入 `/weihubaoyang/MaintainDetail`，参数为 `workorderId`。返回刷新已有 `pageKeyStore` 监听。
- 工作台要求从具体系统卡进入该系统工单范围，但目前 `MaintainList` 无入口参数接收，也无默认系统筛选接线。接入方案待确认后再修改现有页，不在设计稿中假定已支持。
- 原 APP PRD §4.6 的专属搜索占位、三筛选器、结果计数、卡片字段／标记及排序与现有页存在差异。本次按用户指定复用现有页；差异列入 §8，后续决定是扩展现有页还是调整该段验收口径。逾期与即将到期标记仍不得由页面自行推算。

### P3 逾期未完成工单列表（独立页，卡片样式复用）

- 点击工作台逾期卡进入独立 P3。页首汇总卡显示「逾期未完成工单 N 单」，采用现有 `ListCard` 的白底卡、标题／状态双列、次级信息、分隔线和内容区结构，不使用强调色渐变或横向数字统计卡；下方有消防系统、设备类型、位置三个单选筛选器与「当前共查询到 N 个工单」结果计数。
- 工作台逾期统计卡继续显示单数并保持整卡可点击。列表工单卡的背景、边框、标题／状态双列、次级信息和内容区排版参照现有 `src/app/screens-v2/weihubaoyang/Components/ListCard.tsx`；这只确定**卡片样式**，P3 不复用 `MaintainList` 的 Tab、搜索框、筛选配置、列表状态或路由。
- P3 卡片仍需展示 APP PRD §4.6／§4.7 要求的设备编号、消防系统、真实状态、逾期标记、维保周期、设备类型、楼座-楼层和计划完成日期。现有 `ListCard` 不含全部字段，直接复用组件还是提取样式需在实现时确定。
- 范围为登录人可见的全部系统；只展示未闭环、未取消且已过计划完成日期的维保工单，按计划完成日期升序。逾期由服务端判定，页面不按本机时间推算。
- 点击工单进入既有处置页。空态「暂无逾期未完成工单」。

### P4 全年维保完成详情

- 区间快捷项为「当日档／本周／本月」，当日档文案随统计日显示「昨日／今日」；还可自定义起止日期。每次进入默认当日档；切换区间只更新本页。
- 两个底部选择层：楼座默认「全部」，选项来自本租户设备台账实际楼座；楼层随楼座联动，按楼层顺序，未选楼座时禁用并显示「楼层：请先选楼座」。楼座非「全部」时出现重置位置按钮，重置后楼座和楼层均为「全部」。区间和位置筛选互不重置。
- 显示当前生效范围，如「A座-3层」「A座 · 全部楼层」「全部楼座 · 全部楼层」。
- 可展开表格：系统行 → 设备类型行。列为展开标记、名称、日／周／半月／月／季／半年／年；无「设备数量」列、无顶部统计总览。无下级时不显示展开标记。零值格显示「—」，零完成数的行不展示。
- 本页按关闭时间落在所选区间内统计；每列子行合计等于系统行。默认当日档且位置为全部时，表格各周期合计与 P1 完成卡总数一致。统计区间和位置只影响本页。
- 位置下无数据时保留筛选并显示：「该位置暂无维保设备或暂无可统计任务，请更换楼座或楼层。」

### P5 系统维保详情

- 头部：系统名、「维保进度总览」、实际进度、带建议基线的进度条、应维保设备总数、建议进度、历史遗漏任务数。历史遗漏数大于零时整格可点，进入系统级 P6。
- 设备类型行：类型业务真名、设备台数、实际进度、建议进度、判为滞后的周期标签。点击展开标记展开周期卡；仅展示所选年度有计划的类型，按类型字典顺序。
- 周期明细卡按日／周／半月／月／季／半年／年顺序，每个「周期（统计用）」档位一张：周期名、正常／滞后诊断、超期天数（适用时）、实际进度、年检「目标 100%」或其他周期建议进度、进度条、历史完成率与分子分母（无历史段为「—」）。
- 卡底操作条左右等宽：「遗漏 N 单」「剩余 N 单」，整块点击进入对应周期级 P6；N＝0 时置灰且不可点击。
- 头部数值与 P1 对应系统卡同源。计划聚合、FAS 测试计划归属与滞后判定以 Web PRD §4.5.4 为准，页面只展示领域结果。无设备类型时显示「该系统下暂无设备类型」。

### P6 任务明细清单

- 四类入口：P1 系统卡历史遗漏、P5 头部历史遗漏、P5 周期卡遗漏、P5 周期卡剩余。系统级范围文案「系统名 · 历史遗漏任务（全部设备类型与周期）」；周期级「系统名 · 设备类型名 · 周期名」。计数写「遗漏任务 N 单」或「剩余任务 N 单」。
- 任务卡字段：任务编号、真实状态名、计划名称、设备编号与「楼座-楼层」、计划完成日期（已过日期用警示色）。按计划完成日期升序，同一天按任务编号升序。
- 滚动触底加载，每页 10 单；加载中显示「上拉加载更多（已显示 X / Y 单）」，全部加载后显示「已加载全部 N 单」。无筛选、无导出。空态：「暂无数据」。
- 今年视图任务卡可进入既有处置页；去年视图只读，任务卡不可点击。年度始终与 P1 跟踪 Tab 同源。

## 4. 共用交互、组件与状态

| 范围 | 页面生成要求 |

| 表单 | 本范围没有新执行表单；若自定义日期或选择器需要表单能力，使用 `src/components-v2/Form` 的受控接口 |
| 图标 | 使用 `@expo/vector-icons` 的线性图标；具体图标以原型和现有设计体系确认 |
| 追踪 | P0 入口、Tab／年度／范围切换、统计卡、系统卡、遗漏行、展开按钮、周期操作条、工单／任务卡、筛选和重试均需 `trackTarget`；前缀与具体 target 待按 `brain/topics/systems/BEHAVIOR_TRACKING_UI.md` 确认 |

## 5. 接口预留位（不得当作已确认契约）

下表是**页面数据需求槽位**，槽位编号仅用于文档追踪，不是 `apiKey`。后端可以合并或拆分接口；确认前 method、path、字段名、分页结构、样例均保持待定。

| 槽位 | 使用页面 | 所需业务结果 | 输入维度 | Method / Path / apiKey | 正常 JSON 样例 |
|---|---|---|---|---|---|
| A1 | P1 任务 | 统计日、完成总数／个人数、逾期数、按我的／全部的系统剩余与完成数 | 租户／用户权限、任务范围、统计日 | 待确认 | 待提供 |
| A2 | P1 跟踪 | 所选年度系统卡、进度、滞后类型、历史遗漏数 | 年度、租户／用户权限 | 待确认 | 待提供 |
| A3 | P2 复用页 | 现有 `MaintainList` 使用既有列表数据源；如需工作台入口系统预筛选或 PRD 专属字段，确认是否扩展现有契约 | 入口系统、任务范围；具体传参待确认 | 现有接口待核对；新增／调整未定 | 现有样例待核对 |
| A4 | P3 独立页 | 可见范围内逾期未完成工单分页列表、结果总数与筛选选项；是否能复用已有数据接口待核对 | 消防系统、设备类型、位置、分页；逾期条件由服务端处理 | 待确认 | 待提供 |
| A5 | P4 | 区间及位置下的系统／设备类型七周期完成数 | 统计日、起止日期、楼座、楼层 | 待确认 | 待提供 |
| A6 | P4 | 可选楼座与所选楼座下楼层 | 租户、楼座 | 待确认 | 待提供 |
| A7 | P5 | 系统头部、设备类型与周期聚合明细 | 系统、年度 | 待确认 | 待提供 |

每个最终接口补齐以下内容后才能生成 Adapter 和 Service：接口名称、请求方法、完整路径、`apiKey`、请求参数及取值、正常 JSON、畸形／缺字段 JSON、响应字段到页面展示字段的映射、空值和错误码语义、分页与排序责任、`traceId` 来源。接口方法定义处按项目约定写明名称、方法和路径。Service 统一返回 `Result<T>`；Adapter 校验并形成包含 `apiKey`、`fieldPath`、`traceId` 的 `ParseError`；Store 管理 loading／data／error，页面不 import `fetch` 或 `apis`。
